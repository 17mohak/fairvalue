# Player portraits: sourcing, licensing and the asset pipeline

What portraits the site shows, where they come from, under what terms, and how to add or remove one.
The licensed route below (Wikimedia Commons) remains the long-term source; the card portraits that
ship today also include unlicensed FootyLogos images, used at the owner's risk (D-044).

## What ships today: card portraits (D-044, D-053)
Every player is drawn as a **PlayerCard** (direction C, "The Denomination"): the observed
Transfermarkt value as the denomination, ink by value tier, held-out Model A and the residual on the
foot. Rows and thumbnails use **PlayerChip**, the card's small slanted form. Card faces show only
Transfermarkt value, club, league and held-out Model A. Portraits are a presentation layer and say
nothing about the model or the audit.

| Source, in order of preference | Players | Licence | In git |
|---|---|---|---|
| FootyLogos head-and-shoulders cutout | 866 | **None** (unlicensed; D-044) | No: `web/public/players/portraits/cards/fl/` and `web/src/data/generated/portrait_cards_fl.json` are git-ignored |
| Berlin / WikiPortraits frame, background removed by us | 57 | CC BY-SA 4.0 (the edit is shared under the same licence) | Yes: `web/public/players/portraits/cards/berlin/`, `web/src/data/portrait_cards.json` |
| FootyLogos close-up (a tight face, no shoulders) | 262 (22 more were replaced by Berlin frames) | **None** | No |
| Engraved monogram (no image) | 4,635 | n/a | n/a |

Counts come from `research/portrait_sourcing/portrait_plan_all_players.csv` (5,820 players).

- **Build:** `scripts/portraits/build_card_assets.py` makes both sets from the untracked
  `research/portrait_sourcing/` folder. After any rerun, check `git status`: a stale run once
  overwrote the committed Berlin files; restore them with `git checkout`.
- **Clean checkouts** (CI, a new deploy folder) have no FootyLogos files. `npm` writes an empty
  `portrait_cards_fl.json` before dev, build, typecheck and test, so the site builds and shows
  monograms instead. A deploy must copy the images and the JSON in first (`docs/DEPLOYMENT.md`).
- **Takedown switch:** build with `NEXT_PUBLIC_FAIRVALUE_FOOTYLOGOS_PORTRAITS=off` to remove every
  unlicensed image at once (build-time, so rebuild and redeploy). To remove one player, delete their
  entry from `portrait_cards_fl.json`; they fall back to the monogram.
- **Credits:** `/credits` lists every source, its terms and a takedown contact. **Open:** the
  contact is GitHub issues on `17mohak/fairvalue`, which is a private repository, so people outside
  it cannot use it; the owner needs to choose a reachable contact before any wider sharing.
  `cardPortraitProblems` (tested) checks that every entry has a credit and source,
  and that unlicensed images claim no licence and live only in the FootyLogos folder.
- **Checked by eye:** about 100 of the FootyLogos crops and 4 of the 57 Berlin cutouts. The
  close-up flag (shoulder ratio under 1.3) is a heuristic checked on about 40 images.
- **Open:** personality rights on the Berlin files; permission replies from the leagues (D-053);
  Transfermarkt's own terms.

The finder now URL-decodes Commons file names in full (it previously decoded only `%20`, so names
with brackets were "not found"). It batches 50 files per Commons request, retries 429 and 5xx
responses with backoff (honouring Retry-After), and prints UTF-8 on Windows consoles.

Run it with:
```bash
WIKIMEDIA_CONTACT="you@example.org" ./.venv/Scripts/python scripts/portraits/find_candidates.py --from-export
```
It takes about 15 minutes for 5,820 players, including the rate-limit pauses.

The licensed cutout pipeline below (finder, add helper, `portraits.json` manifest) is tested end to
end, but `portraits.json` itself still lists no full-size cutout: the dossier uses the card
portraits above.

## Ruled out
| Source | Why not |
|---|---|
| `image_url` in the Transfermarkt players table | Transfermarkt's own photos; copyrighted and not covered by the dataset's CC0 licence, which covers the data. The export never reads this column. |
| Club websites, media kits, press galleries | Licensed to media for editorial use, not for reuse in a product. |
| Agency photography (Getty, Reuters, PA and others) | Needs a paid licence per image and use, and model releases for commercial use. |
| Scraping search results | Unknown rights for every image. |
| AI-generated likenesses of real players | Misrepresents real people. |

## The defensible route: Wikimedia Commons via Wikidata
Wikidata links a footballer's **Transfermarkt player ID** (property P2446, the same id this project
uses) to their main image (P18) on Wikimedia Commons. Commons records every file's licence, author
and size. So candidates can be found systematically for any player in the export, with provenance
attached.

**Allowed licences** (`allowed_licences` in `web/src/data/portraits.json`, kept in sync with
`scripts/portraits/licences.py` by a test):

| Licence | Meaning for a cutout |
|---|---|
| CC0, Public Domain Mark | No conditions. |
| CC BY 2.0–4.0 | Credit the author and licence, and say the image was modified. |
| CC BY-SA 2.0–4.0 | As CC BY, and the cutout itself must be released under the same licence. The helper adds "(background removed)" to the credit. |
| `owned` | Your own or commissioned photo, or written permission for this use. Keep the permission on file outside the repository. |

Never allowed: NonCommercial (NC), because public deployment may count as commercial; NoDerivatives
(ND), because a cutout is a derivative; fair-use or non-free files; GFDL-only files.

**Personality rights.** A copyright licence does not cover the subject's image rights. Commons marks
many photos of people with a personality-rights notice; the finder reports it. Using a portrait on a
profile that sits next to a model estimate is low risk for a private, non-commercial project. For public
deployment, get advice on this specific use.

## Steps
1. **Find candidates.** On a machine with internet access:
   ```bash
   ./.venv/Scripts/python scripts/portraits/find_candidates.py
   ```
   This defaults to the eight showcase players; `--from-export --limit 200` covers the 200 most
   valuable players in the full export, and `--download` also fetches allowed originals. It writes
   `data/interim/portrait_candidates.csv` (git-ignored) with one row per player: licence as shown on
   Commons and normalised, allowed or not, author, pixel size, any restrictions, file page and a
   suggested credit line. Set `WIKIMEDIA_CONTACT` to add your contact to the User-Agent, as
   Wikimedia asks.
2. **Review each candidate** on its Commons file page:
   - the licence section matches the sheet;
   - the photo shows the player, not a crowd or team shot;
   - it is sharp at the size you need, with head and shoulders unobstructed;
   - note any personality-rights notice.
3. **Make the cutout.** Remove the background with any tool. `rembg` (open source, runs locally) is
   one; clean the edges by hand. Export PNG or WebP with transparency, at least **1400 px tall**
   (1600–2000 recommended), roughly waist-up, with the player facing slightly left.
4. **Add it** (copies to `web/public/players/portraits/<id>.webp` and writes the manifest entry with
   the real pixel size):
   ```bash
   ./.venv/Scripts/python scripts/portraits/add_portrait.py --player-id 849520 --image cutouts/castro.png --licence CC-BY-SA-4.0 --author "Name as on Commons" --source-url "https://commons.wikimedia.org/wiki/File:..." --attribution "Photo: Name / Wikimedia Commons, CC BY-SA 4.0"
   ```
   It refuses a licence outside the allow-list, an image without transparency, or one under 1400 px.
5. **Test.** Run `cd web && npm test` and `./.venv/Scripts/python -m pytest -q tests/test_portraits.py`.
   They check every entry's licence, credit, source and local file, and that the file's real size
   and transparency match the manifest. Open the profile and check the composition at desktop and
   phone widths.
